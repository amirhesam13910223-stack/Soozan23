# سیاست تست و کیفیت — سطح: فوق‌قوی
لایه‌ها: unit (قوانین نابودی، ماشین‌های حالت) → contract (OTP، ویزارد، دریافت) → integration E2E (سهم کامل) → security regression (خط قرمزها + جداسازی) → resilience/chaos → load/stress + DDoS شبیه‌سازی‌شده → backup-restore drill → UI/RTL snapshot.

## سناریوهای طلایی (هر فاز سبز نگه‌شان می‌دارد)
۱) اشتراک با هر حالت نابودی ⇒ بازدید دقیق ⇒ نابودی دقیق.
۲) OTP: lock پس از ۴ تلاش، expiry، resend با کد/زمان جدید.
۳) «پایان همه نشست‌ها» ⇒ همه‌ی دستگاه‌ها بیرون + ورود کامل اجباری.
۴) اسکنر: رد اجرایی، قرنطینه‌ی آرشیو آلوده، عبور فایل تمیز.
۵) کد اشتراک فقط یک‌بار نمایش؛ بار دوم بازیابی‌ناپذیر.
۶) وب: ماندگاری تیک «دیگر نشان نده» + یادآور متنی صفحه‌ی کد.
۷) جداسازی/RLS: کاربر A با هیچ عملیاتی به ردیف کاربر B نمی‌رسد؛ کوئری بدون context ⇒ صفر ردیف.
۸) بار: ۱۰۰ کاربر همزمان ⇒ بدون crash، صحت نابودی ۱۰۰٪، صف‌ها تخلیه، p95 در سقف (templates/38).
۹) بازیابی: بازگرداندن DB و کلیدها از بک‌آپ ⇒ سیستم کامل کار می‌کند و نابودی‌ها درست ادامه می‌یابند.
۱۰) حمله: شبیه‌سازی DDoS + کاربران مشروع هم‌زمان ⇒ مشروع‌ها سرویس می‌گیرند، هسته سالم می‌ماند.

## اصول کیفیت
- صحت نابودی هرگز flaky نیست؛ تست نارنجی = توقف، نه رد شدن.
- تست‌های امنیتی/جداسازی/بک‌آپ با هر تغییر مرتبط دوباره اجرا می‌شوند، نه فقط پایان فاز.
- هر باگ ⇒ اول تست بازتولید، بعد اصلاح، بعد ثبت در memory/42.
- مانور بک‌آپ و مانور حمله به‌صورت دوره‌ای و پایان هر فاز اجرا و ثبت می‌شوند.
